## 1. T_can statement

T_can is the pair of **canonical object identities**:

    (T_can-H) C9Hull = IIIHull,
    (T_can-Q) C9QPilot = IIIQPilot.                              (1.1)

Here:

- IIIHull is the IUT III holomorphic hull of the union of possible images of
  the Theta-pilot object under (Ind1),(Ind2),(Ind3) [Remark3.9.5(i);
  Corollary3.12 Step(xi)];
- IIIQPilot is the IUT III q-pilot object determined by the q_v, v in V_bad,
  in the global realified Frobenioid [Definition3.8(i)];
- C9Hull is the C9 target holomorphic hull H_C;
- C9QPilot is the C9 native q object/native q with Q_C.

T_can is **not** the normalization identity T_norm. It is an identity of
objects, not of log-volume functionals or numerical values.

## 2. Verdict

T_can is **not proved by IUT III alone**. It has two exact branches:

(D) Definitional branch. If the C9 target is instantiated as the source hull
    IIIHull, and the C9 native q object is instantiated as the source q-pilot
    object IIIQPilot, then T_can holds by definition. This is a definitional
    choice of C9 target, not a theorem derived from IUT III.

(G) Gap branch. If C9Hull is an abstract C9 target hull and C9QPilot is only
    a C9 native q scalar/readout (e.g. Q_C=-(b/41)logp), then T_can is an
    exact gap: IUT III does not assert an object identity, and no canonical
    comparison functor is supplied. Equal normalized log-volumes would not
    imply equal objects; a factor 41 or any normalized surrogate cannot
    replace the object identity.

The frozen C9 master treats C9Hull/C9QPilot as target/native objects with
TC/C6 alignment conditions, not as definitionally equal to the source objects.
Therefore T_can is currently **open/exact gap**, not a proved theorem. P6_can
is not established by T_norm alone.

## 3. T_can-Q: why object identity is missing

IUT III Definition3.8(i), lines 6506-6544, defines the q-pilot object as the
object of the global realified Frobenioid determined by a **collection** of
generators up to torsion of the splitting monoid associated to the split
Frobenioid; concretely, determined by the q_v for v in V_bad.

Two object-level facts:

- IIIQPilot is an object in the global realified Frobenioid, not a real number;
- the q_v are taken up to torsion, so IIIQPilot has an O_K^times/torsion
  indeterminacy; it is not a single canonical q element.

C9QPilot in the C9 normalized formulation is the native q object whose
log-volume readout is Q_C=-(b/41)logp. If C9QPilot is only that scalar/readout,
there is no object identity with IIIQPilot: a numerical log-volume does not
determine the underlying q-pilot object.

A proof of T_can-Q would need one of:

(Q1) define C9QPilot := IIIQPilot (definitional branch D); or
(Q2) construct a canonical object isomorphism between the C9 native q object
     and the source q-pilot object, compatible with q_v and its torsion
     indeterminacy; or
(Q3) prove that the C9 native q is the same Frobenioid object, not merely the
     same log-volume/scalar.

None is in the frozen source. The 82-root/valuation computation fixes the
log-volume -|log q|=-(b/41)logp, but it does not identify C9QPilot with the
source q-pilot object.

## 4. T_can-H: why hull identity is missing

IUT III Remark3.9.5(i), lines 7745-7755, defines the holomorphic hull as the
hull of the union of possible images of the Theta-pilot object; Corollary3.12
Step(xi) forms the union subject to (Ind1),(Ind2),(Ind3).

C9Hull is the C9 target holomorphic hull H_C. To identify it with IIIHull one
needs:

(H1) the C9 possible-image union equals the source union over labels/places;
(H2) the C9 Ind1/Ind2/Ind3 treatment equals the source treatment;
(H3) the C9 hull operation equals the source lambda·O hull;
(H4) the C9 target normalization/TC data are the source target data.

These are object-level comparisons. T_norm equates normalized log-volume
functionals once the objects are common; it does **not** prove the objects are
common. Equal values on a common region do not imply equal hulls.

A proof of T_can-H would need one of:

(H1') define C9Hull := IIIHull (definitional branch D); or
(H2') construct a canonical isomorphism of the possible-image unions and hulls
      compatible with Ind1/2/3 and the target normalization; or
(H3') prove that the C9 H_C is exactly the source hull, not an abstract target
      hull with TC conditions.

None is a theorem of IUT III. The frozen C9 target has TC-A..H/TC-S and C6
alignment as separate conditional inputs; those are not object identities.

## 5. Why normalization cannot substitute

T_norm gives, conditionally:

    C9LogVol = IIILogVol,
    h_C = -|log Theta|,
    Q_C = -|log q|.                                              (5.1)

But (5.1) is an equality of **log-volume values**, not of objects:

- two different q-pilot-type objects can have the same log-volume without
  being the same object;
- two different hulls can have the same normalized volume without being the
  same hull;
- the factor 41/1/m/82 normalizations are numerical readouts, not object
  isomorphisms.

Therefore T_norm does not imply T_can. A "normalized surrogate" P6_can that
replaces object identity by log-volume equality is not the canonical P6_can
statement. No factor 41 can bridge the gap.

## 6. Conditional theorem (definitional branch)

Theorem 6.1. If C9Hull is defined to be IIIHull and C9QPilot is defined to be
IIIQPilot, then T_can holds as a definitional identity; consequently, with
T_norm, P6_can follows from Corollary3.12.

This theorem is a definitional instantiation, not a source theorem. It makes
T_can true by choosing the C9 objects to be the source objects; it does not
prove that an independently defined C9 target/native q equals them.

## 7. Exact gap

The exact missing data are:

(TG1) an object-level identification C9Hull = IIIHull (possible-image union,
      Ind1/2/3, hull operation, target normalization);
(TG2) an object-level identification C9QPilot = IIIQPilot (q_v collection up
      to torsion, Frobenioid object, not just its log-volume);
(TG3) compatibility of these objects with the C9 target C6/TC data and the
      source 1-column/Theta-pilot data.

Without TG1-TG3, T_can is open. T_norm and the q-value computation fix
numerical readouts only; they do not close the object identities.

## 9. Conclusion

T_can is not a consequence of IUT III or of T_norm. The source defines the
q-pilot object and the holomorphic hull; C9 defines its own target hull and
native q. Their object-level identity is an additional instantiation
(TG1-TG3), not a normalization identity. If C9 defines its objects to be the
source objects, T_can is definitional; if C9 keeps abstract target/native
objects, T_can is an exact gap. Equal normalized log-volumes (T_norm) and the
numerical q-value do not imply object identity. P6_can remains conditional on
T_can; no normalized surrogate or factor 41 is used.
