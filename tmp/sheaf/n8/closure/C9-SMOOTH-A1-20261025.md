## 0. Question

Smooth A1 must resolve four apparent choices in the q-pilot/BPS input:

(a) q_v only up to torsion vs a canonical q;
(b) full poly-isomorphism class vs a chosen BPS object;
(c) collection of possible output data vs a section;
(d) derivation of the q-pilot F^value × mu input/0-column from the source definitions.

## 2. Smooth A1 statement

**Theorem (Smooth A1).** In the situation of Theorem3.11/Cor.3.12, the q-pilot/BPS input is canonical at the following exact level:

    A1 = ( [F^⊩▶×mu] , Q_pilot ),                               (2.1)

where:

- `[F^⊩▶×mu]` is the **full poly-isomorphism class** of F^⊩▶×mu-prime-strips in the log-theta-lattice; no representative isomorphism is chosen;
- `Q_pilot` is the q-pilot object of `C^⊩_Delta` determined by any collection of generators up to torsion of the splitting monoids at v in Vbad; it is independent, up to canonical isomorphism, of the generator collection;
- the q-pilot log-volume `-|log(q)|` is well-defined on this object/class and is independent of the generator/torsion choices and of the full poly-isomorphism representative.

Thus A1 is a **class/object-level canonical input**: no canonical q_v, no chosen BPS representative, and no section are required. The q-pilot F^value × mu input and the 0-column data are derived from the source definitions (1) and the LGP-link (1.1), not chosen.

## 3. Resolution of the four choices

### 3.1 q_v up to torsion vs canonical q

`q_v` is not canonical: Definition3.8(i) allows any collection of generators up to torsion. But the resulting q-pilot **object** in the global realified Frobenioid is independent of the generator collection: torsion/root ambiguities are precisely what the realification and `up to torsion` clause remove. Therefore the canonical object is `Q_pilot`, not a canonical scalar `q_v`. The log-volume `-|log(q)|` depends only on `Q_pilot`, hence is well-defined.

### 3.2 polyiso class vs object

The BPS input is not a chosen F^⊩▶×mu-prime-strip object but the full poly-isomorphism class `[F^⊩▶×mu]`; Definition3.8(ii) defines the LGP-link as the full poly-isomorphism (1.1). Choosing a representative would be arbitrary and is excluded. All log-volume comparisons are invariant under full poly-isomorphism, so the class suffices for A1.

### 3.3 output collection vs section

The multiradial output is a collection of possible images/output log-volumes, not a section. A1 supplies the q-pilot value as one fixed element of that collection (via the q-pilot object); A2/A3 then compare the collection/hull with this fixed value. No section of the output family is chosen.

### 3.4 q-pilot F^value × mu input / 0-column

The q-pilot F^value portion is the value-group portion of the F^⊩▶×mu-prime-strip in (1.1); the mu portion is the associated unit/cyclotome data. The 0-column is the vertical line n=0 of the log-theta-lattice; its `(0,circumflex)` structures are constructed from the unit portion, bi-coricity and log-Kummer (Cor.3.12 Steps (iii)-(v)). A1 therefore uses the source-defined 0-column, not an extra chosen column.

## 5. Exact gaps

1. A **canonical scalar q_v** or a chosen generator section does not exist. This is not a gap for A1: Definition3.8(i) works with generators up to torsion and the q-pilot object.
2. A **chosen representative** of the full poly-isomorphism class does not exist canonically. This is not a gap for A1: A2/A3 use full-poly-invariant log-volumes.
3. An **explicit E_546 b=273** q-pilot/BPS object with concrete q_v values, 0-column labels and target data is still not constructed. This is a concrete-instantiation gap, not a smooth-A1 source gap; the universal P6 theorem does not require it.
4. The source's A2 determinant/log-volume comparison remains semantic/construction-computational rather than an explicit numerical algorithm; this is the task-379 formalization gap, not a q-pilot canonicality gap.
