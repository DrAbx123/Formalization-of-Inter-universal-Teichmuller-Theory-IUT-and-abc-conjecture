## 2. Exact comparison object

The compatible comparison preserving all factors is the base-change map

( tensor over Q of M_i )  tensor over Q of Q_p
  ~=  tensor over Q_p of M_i,

where M_i = CommonPrimeCompletion (t i).  It keeps the same index type Capsule j
and the same factor at every label; no factor is dropped.

## 3. Exact first field

The first missing object is the actual base-change equivalence

  rationalBaseChangeQp :
    ( rational tensor ) tensor[Q] Q_p  ~=  Qp tensor

or equivalently a Qp-linear comparison obtained by scalar extension of the
rational tensor.

A direct Qp-linear map on the rational tensor is not available: the rational
tensor is only a Q-vector space.  The naive pure-tensor map to the Qp tensor is
surjective but has the kernel generated by the Q-relations
  c * (x_i) - (algebraMap c) * x_i,
so it is not the paper's compatible comparison.

## 4. Why no Lean file

Mathlib v4.32.2 has PiTensorProduct and general TensorProduct base change, but
no PiTensorProduct scalar-extension equivalence
  (PiTensorProduct over Q) tensor[Q] Q_p  ~=  PiTensorProduct over Q_p
for a finite family.  Writing it is a substantial construction; a file with only
a Prop/Nonempty predicate would be a fake comparison.  The exact first field is
recorded instead.
