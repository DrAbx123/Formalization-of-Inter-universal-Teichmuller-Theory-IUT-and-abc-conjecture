# S1259: can Ind1/2/3 be built from family.permutation / index_equiv?

Date: 2026-10-30.  Read-only audit; no Lean, no new wrapper.

## Verdict

**No.**  `OriginalInput` carries only `initial`, `family`, `index_equiv`, and
`arithmetic_alignment`.  `SourceHodgeTheaterFamily` carries `index`, `theater`,
`distinct`, `link`, the link laws, `permutation : Equiv.Perm index`, and
`permutationLink : HodgeTheaterLink (theater (permutation i)) (theater i)`.
These data do not construct the paper's Ind1/2/3 actions.

## 1. `index_equiv`

`index_equiv : family.index ≃ Int × Int` is only a coordinate identification
of the family index with the `(n,m)` lattice.  It supplies:

```text
indexOf n m : family.index
theaterAt n m, linkAt n m n' m'
```

but no group action of the Ind1/Ind2 label groups, no capsule assignment, no
Fmod unit copies, and no times-mu action.  It therefore gives only the
indexing needed to refer to `fPrimeStripAt`/`fLinkAt`; it is not an Ind action.

## 2. `family.permutation`

`permutation : Equiv.Perm family.index` is a single permutation of the family
index, with a link `permutationLink i : HodgeTheaterLink (theater (perm i))
(theater i)` and naturality with `family.link`.  This is a candidate symmetry
of the indexed family, not the paper's Ind1/2/3:

* it is not a homomorphism from the Ind1 label group to `Equiv.Perm index`;
  the family carries one permutation, not the label action;
* its `permutationLink` is a link between different theaters, not an
  automorphism component at a fixed theater;
* it has no data at the capsule/tensor level (`Capsule`, `VQ`, `logShell`,
  `Fmod` unit copies, or `TimesMuQuotient`);
* it gives no Ind2 independent-copy action and no Ind3 upper-semi/log-link
  action.

At best one can form the cyclic subgroup generated by `family.permutation`
(powers of one permutation) on `family.index`, but this is not the Ind1 group
action of the paper and has no compatibility with the actual capsule/tensor
Ind1/2/3 actions.

## 3. What each actual action needs

### Ind1

`Ind1AutomorphismTensorActionActual.PrcAutomorphismTensorAction` consumes a
`PrcAutomorphism A j`, which has:

```text
perm : Capsule j.val ≃ Capsule j.val
component : ∀ i, FPrimeStripEquiv (PrcMember A j i) (PrcMember A j (perm i))
```

from an actual `CapsuleTheaterAssignment`/`SourceProcessionCapsuleContract`.
`family.permutation` lives on `family.index`, not on `Capsule j.val`, and has no
`component` field.  So no actual Ind1 action follows.

### Ind2

`Ind2TensorActionActual.ind2TensorEquiv` consumes `f : Capsule j.val → Rˣ`
(independent Fmod-unit copies acting per tensor factor) and the actual tensor
packet `SourceProcessionCapsuleContract.tensorPacket`.  `family` has neither
the capsule factor index nor the unit-copy family.  No actual Ind2 action
follows.

### Ind3

`GlobalKummerIndActionsActual.actualInd3Data` consumes the source strips
`I.fPrimeStripAt 1 m`, their times-mu actions, and `TimesMuQuotient` stage
comparisons.  `index_equiv`/`permutation` give no `m`-indexed times-mu action
or stage comparison.  No actual Ind3 action follows.

## 4. Exact missing objects

```text
Ind1: actual CapsuleTheaterAssignment + SourceProcessionCapsuleContract
      + PrcAutomorphism data (perm + component FPrimeStripEquiv)
Ind2: actual capsule factor index + Fmod-unit copy family on tensor factors
Ind3: actual m-indexed fPrimeStripAt/times-mu action/comparison data
```

These are exactly the source objects already consumed by
`Ind1AutomorphismTensorActionActual`, `Ind2TensorActionActual`, and
`GlobalKummerIndActionsActual`; `family.permutation`/`index_equiv` are not
substitutes for them.  No new Lean is written.

## 5. Consequence

One cannot prove the Ind1/Ind2/Ind3 action laws on `Choice = family.index` from
the current `OriginalInput` data alone.  The earlier S1233 possibleImage laws
were possible precisely because `possibleImage` was made independent of the
index; they do not construct a `DPrimeStripProcession` on `family.index`.

A genuine Ind-procession on `family.index` remains an exact source obligation,
not a consequence of `family.permutation`.
