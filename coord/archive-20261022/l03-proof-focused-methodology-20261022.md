# 面向项目证明的 L0.3 实施方法

2026-10-22。本文修改工作方法和验收标准，不修改 Lean 源码，不宣布新的数学结果。

**目标：把已有的一般有限 étale 商理论接到项目实际需要的 G2 和源基本群证书。每包工作说明消掉哪个既有前提，完成到对应消费者，不以文件数、通用性或包装层数计进度。**

本文依据 [L0.3 消费者核对](D:/lean/tmp/l03-direct-consumer-audit-20261022/consumer_trace.md) 和 [已记录的较短路线](D:/lean/logs/coordination/l0-shorter-routes-20261021.md)。源码状态会变化；后续先复用这些结论，仅核对影响本包的更新，不重复全仓审查。

## 1. 先判断与证明的关系，再按难度安排

选题顺序是：项目关联成立 → 前置可用 → 找最短路线 → 在可完成的问题中优先处理重要难项。

| 证据 | 是否足以开始工作 |
|---|---|
| 现有主线证明已经调用该结果，当前因这个结果或接口缺失而受阻 | 可以，直接消除阻塞 |
| 已有消费者的完整类型明确缺少它，实际对象、参数和比较均已核对 | 可以；不要求未完成的调用先编译，但要有明确接入方式 |
| 有必要的中间数学缺口，已经核对它到上述消费者的依赖 | 可以；明确完成它后减少哪项前提 |
| 只有论文锚点、Source/Actual/Final 文件名、Project import、概念相近或“以后可能有用” | 不足；先定位消费者，不扩写实现 |

没有直接文本引用不等于数学无关；有 import 也不等于证明需要。核对声明的完整类型和构造来源。消费者记录本身不能通过新建一个空 card 来制造。

“难但会做”只在前面三类中排序。无关的难题不优先；已能机械处理的类型、日志、路径和重复构建问题先走现有脚本。

## 2. 用一个可验收终点定义 L0.3 的范围

在实际所需基底 S 上，有限群商的核心目标是：对每个有限群 G，有限 étale 覆盖范畴具有 SingleObj G 形状图的余极限，即

```text
∀ G [Group G] [Finite G],
  HasColimitsOfShape (SingleObj G) (FiniteEtaleCover S)
```

这里必须覆盖该范畴中任意作用图，不能只完成平凡作用、regular permutation 或自由作用。

实施时分别报告两种完成状态：

- **商/G2 数学核心完成**：原输入作用图的真实商、投影、因子分解、唯一性和 IsColimit 已证明并验证。
- **实际源消费者接入完成**：这个结果在项目要求的实际对象上被调用，消掉指定源接口的前提。

第一种是有价值的数学前置，但不能自动报告为第二种。只返回多个旧结论的合取，不会产生新的源接入。

G2 是基本群证书的一部分。完成 G2 不等于完成 fiber functor、公理的其余部分、算术基本群正合列或 tempered 理论。

## 3. 每包工作只写一份简短任务说明

开始前填清以下六项，写入既有研究记录即可，不新建调度平台或 Lean 数据结构：

| 项目 | 要写的具体内容 |
|---|---|
| 原目标 | 对象、变量、量词、假设、结论 |
| 消费者 | 已有文件和声明；它缺哪个字段、引理或比较 |
| 对象来源 | 基底 S、cover X、原作用 act、相关范畴和 fiber 从哪里构造 |
| 已有供体 | 已证明的声明及适用范围；不能只写“某文件已完成” |
| 本包增量 | 实际要证明的缺口，或必要的对象/态射比较 |
| 验收出口 | 原消费者的调用或实例；若尚缺另一条桥，写明精确剩余项 |

避免任务名“继续完善商理论”“统一所有入口”“把 gluing 全部做完”。可采用“从原 cover action 构造同一覆盖范畴内的 IsColimit，并填写指定 G2 字段”。

文件名单以实际需要为限；同一文件保留唯一 owner。普通证明体、局部 API 修复和验证在已授权整包内连续完成，不逐行申请确认。

## 4. 优先复用目前可走的仿射短路线

若实际基底已有 S≅Spec R 的证明，则使用现有表示，不重建源图表拼接。对于实际 X/S 和 act:G→Aut X：

1. 从 X→Spec R 的有限 étale 性导出 X 仿射及 Γ(X) 的相应代数性质。
2. 复用实际截面作用构造，固定反变与逆元的约定。
3. 复用一般不变量定理，构造 Q=Spec(Γ(X)^G) 及其有限 étale 结构。
4. 构造原 cover 上的 π:X→Q，证明原 act 下的不变性。
5. 对任意目标 cover Y 和 invariant f:X→Y，构造唯一的 cover morphism Q→Y。
6. 组装原作用图的 Cocone/IsColimit，再得到任意 SingleObj G 图所需的实例。

输入中的 Γ(X) 作用、R-代数结构、仿射识别和相容性，优先从同一个 X、act 构造。不能把应证明的比较重新留给调用者填写。

已有一般定理适用于任意 R，就直接复用；不为“source 专用”再复制一套证明。反过来，也不为更广的底对象另建消费者不需要的理论。

两个具体的省事接法：

- 截面作用若用 g⁻¹，而自然性公式用 g，显式做一次逆元换元，统一后续约定；不再造第二套作用。
- 已有 affine-target 唯一分解时，factor 的 over-R 方形可比较 u≫Y.structureMap 与 Q.structureMap。它们与 π 复合后相同，用同一普遍性对 Spec R 的唯一性完成；不必先开发一般 scheme epi 理论。

这条路线在仿射范围内成立。非仿射底、非可表示 orbicurve、任意 scheme 目标的更强普遍性若确为原目标所需，保留其真实下降/粘合义务；不能借短路线减少量词。

## 5. 源接入只做缺失的实际比较，不反复重做测试曲线

已查实的范围：

- y²=x³−x 已被明确标成测试实例；generic FiniteEtaleCover/G2 不依赖这条固定方程。
- 项目源构造的具体消费位置包括 SourceCompletionSignQuotient.xFGroups/cFGroups。
- 其基本群证书使用实际 OrbicurveFiniteEtaleCover、GaloisCategory 和自然的几何 fiber 识别。
- 当前 SourceOncePuncturedGeometry curve X 只记录签名；已有定理证明该条件不约束 curve。不能靠它验收实际源识别。

据此安排工作：如果已有实际源 scheme 表示，复用它并建立与相应 orbicurve 的覆盖范畴、态射及 fiber 比较。如果还没有，记录这个准确的对象比较缺口，不回到另一个固定曲线例子，也不再添加“同签名即可”的包装。

识别一般 puncture 补集时，不能默认它就是原 Weierstrass 仿射图；只有 puncture 对应无穷远点或已有实际平移同构时，才能这样使用。此项是表示比较的检查，不意味着重开整个曲线理论。

源几何、Native→旧 contract、3.11 的 P1/P2 供给属于不同接口。不要让一个 L0.3 包承担全部源构造，也不要把从任意较弱算术输入构造合格 initial-Theta 数据擅自增加为3.11的前提。

## 6. 允许换路线，先核对是否等强

新路线只需列出四件事：原目标；替代步骤；可复用的真实供体；剩余精确接口。用户已允许先交草稿，不要求所有捷径立即形式化。

| 检查 | 合格标准 |
|---|---|
| 对象 | 仍是原 X、act、基底和源输入；替代表现有实际比较 |
| 量词 | 任意原输入没有变成单个例子；一般作用没有变成自由作用 |
| 假设 | 没有新增原上下文无法证明的 Normal、Free、Noetherian、群阶可逆等条件 |
| 结论 | IsColimit、原投影、因子分解及必要自然性仍完整 |

成功例子是已完成的 puncture ideal：利用 Mathlib 的实际可逆分式理想，得到原理想模块的投射性和秩一，省去先建立 Dedekind 理论的前置。

L0.3 可用的替代是仿射底上的 Γ(X)^G 构造，省去不必要的源图表拼接。它不能自动替代任意非仿射底的全局结论，也不能自动证明一份外部任意给定的 chart data 与这个商相容。

草稿留在文档中，注明未证步骤。不要把草稿变成带未证字段的 Lean 上层模型，再以此继续推进。

## 7. 遇到这些情况，停止扩写该分支

| 情况 | 应采取的动作 |
|---|---|
| 下一项只能解释为“以后可能有用” | 暂不开始，先定位实际消费者 |
| 新结构把本包要构造的商、相容性或普遍性直接当输入 | 回到底层缺口，不继续包装 |
| projection 实际是一个同构，只证了双侧作用的等变性 | 不按商验收；若只是另一条作用运输分支，停止向商主线计进度 |
| gluing 的 universal 漏了重叠相容前提 | 不把它用作一般粘合供体；有主线消费者才投入修复 |
| 当前只有 regular permutation，原目标是全部作用 | 保留特例，转向一般构造，不继续增加特例消费者 |
| 新入口只是旧结论的合取或改名 | 不作为新数学交付，不继续扩层 |
| 准备重证已经存在的通用结果 | 核对完整类型，直接实例化或补实际转换 |
| 原任务需要的前置尚未证明 | 停止该依赖分支，记录精确前置；继续真正独立且相关的工作 |

发现错误不意味着应立刻修完该文件。无主线消费者的分支可以保留历史并停止使用，不为“整理干净”展开大重构，也不删除已有正确证明。

## 8. 保护算力：调查只做到足以决策

已有研究结论先查记录。没有新定义、新依赖、编译失败或实际对象变化，不反复审计同一条曲线或同一处旧问题。

检查引用时区分：仅 import；声明之间真实调用；已消除实际消费者前提。文本检索没有命中只能说明该范围内未见直接引用，不能冒称 kernel 依赖证明；文件名和注释也不能代替命题类型。

低级错误按 [现有自动化说明](D:/lean/tools/LEAN_AUTOMATION_USAGE.md) 分流。资源等待、缺失产物、重复日志、同版本失败先由脚本处理。需要数学判断的才进入证明探索。单 agent 要求继续有效，不因包的划分派出新 agent。

开发中保留解除真实阻塞所需的局部检查；批次末做约定的完整构建和审计。不为写每个小包装反复全 Project 构建。相同版本已有证据可以复用，但要标明复用；新版本不能沿用旧绿色状态。

若要用例子检查构造，选择少量能暴露错误的情况：非平凡作用检验投影没有错误地成为同构；带稳定子的作用检验没有误限于自由作用。它们作为检验，不再发展成新的生产理论分支。

## 9. 验收报告只保留能判断推进的信息

使用下面的简短格式：

```text
原缺口：已有消费者 C 缺少什么。
实际对象与量词：本结果对谁成立，保留哪些假设。
本包证明：新增或复用的准确声明。
接入：C 的哪项前提已消除；尚未接入则明确写出。
验证：对应文件版本的编译、公理及必要语义核对。
剩余：下一条精确缺口，不泛称“最后一些接线”。
```

普通条件定理若其条件正是待证结论，不能作为闭合。保留原定理合法输入不属于造假；必须分清数学题目允许的假设与本包为了绕过缺口新增的假设。

不要用“Project 已导入”“增加多个 Actual/Final 文件”“无 sorry”“接口可以 inhabit”单独判定项目证明前进。编译和公理检查确认形式证明边界；源对象及原文忠实性由实际比较和消费者使用确认。

## 10. 当前建议的工作顺序

1. 固定已有消费者及原 G2 量词，确认所需基底/范畴和实际源表示。
2. 复用 generic invariants、M1、真实截面作用，完成同一 cover 范畴内的一般商及 IsColimit。
3. 填实际 G2 实例；将缺失的源覆盖范畴/纤维比较作为明确接入任务，不用新包装代替。
4. 在指定源消费者中消除前提，分别记录数学核心与源接入的完成状态。
5. 达到本包目标后停止扩展。只有新的实际消费者要求更强结论时，再增加对应一般性。

这套顺序不要求一次完成整个IUT源构造，也不允许把一般商数学核心当作全部source基本群已完成。它要求每笔投入都有明确的证明出口。
